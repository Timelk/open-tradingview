# 本地行情存储、录制与深度采样

本地 Node 服务将公开行情保存在项目的数据目录中，供重读、聚合与回放使用。**人工录制和图表深度采样是两套独立的存储与生命周期**；关闭浏览器、停止服务、重启服务的效果不同。

## 两套 SQLite 存什么

以下是从仓库根目录启动服务时的默认位置：

| 文件 | 内容与用途 |
| --- | --- |
| `.data/market/market.sqlite` | 数据集清单、导入任务、公开成交、录制的深度快照/差分、缺口与接收时间，以及品种目录和连接器配置；用于档案研究与按时间回放 |
| `.data/depth/depth-samples.sqlite` | 被观看品种的压缩、分桶深度样本及观看列表；用于图表热图的近期历史，不保存完整成交或逐条深度差分 |

两库都使用 SQLite WAL，运行时可能伴随 `-wal` 和 `-shm` 文件。行情档案目录另有 `writer.lock`，防止多个本地服务同时占用同一写入目录；`tmp/` 用于下载或上传的临时 ZIP，处理结束后清理。

浏览器保存的布局、绘图、指标和偏好使用 localStorage；历史行情缓存使用 IndexedDB，兼容保留既有库名。它们并不都存进上述 SQLite。换浏览器或清理站点数据与删除服务器数据目录是不同操作。备份 SQLite 时应先停止本地服务后复制整个对应目录，或使用支持 WAL 一致性的备份方式；运行时只复制主 `.sqlite` 文件可能遗漏尚在 WAL 中的数据。

## 档案导入与人工录制

**档案导入**支持 Binance USDⓈ-M 的 `aggTrades` / `trades` 日档、月档及日期范围。服务器只根据校验后的品种、类型与日期构造公开档案路径；下载后核对 SHA-256 CHECKSUM，再流式解析并写入 SQLite。也可上传 ZIP 并提供校验值，此时来源会明确标为用户上传。未完成、失败或取消的文件不能当作完整档案使用；已完成且校验一致的文件可复用。

**人工录制**需要明确启动。服务器独立连接公开成交和 L2 深度，保存已验序快照、差分、接收时间与缺口；最多同时录制 4 个品种。成交断流有有限补取，未补齐的 ID 缺口仍会保留，不能把有限补取描述为完整历史恢复。

| 操作 | 人工录制的效果 |
| --- | --- |
| 关闭面板或浏览器 | 本地 Node 服务仍在运行时，录制继续 |
| 停止录制 | 关闭对应连接、落盘并记录停止边界 |
| 正常关闭本地服务 | 停止录制、取消导入、等待在途上传结束并关库；已保存数据保留 |
| 服务重启 | 可重读已有数据；遗留录制状态变为停止，中断导入标记失败，不自动续录 |
| 人工恢复同一录制数据集 | 建立新连接，保留暂停区间；等待新的真实快照与连续差分后恢复可用 L2 |

## 图表深度采样

采样器随本地开发或预览服务启动。图表观看品种后，服务器为其维持公开订单簿，在数据处于实时且足够新鲜时保存分桶样本。默认 **15 秒一个样本、保留 2 天、最多同时 3 个最近观看品种**，旧样本按小时清理。

- 关闭图表页面后，只要服务器仍运行，已观看品种的采样可以继续。
- 停止服务器会停止采样，但已落盘且未被清理的样本保留。
- 重启服务时，采样器从持久化观看列表恢复最近品种的订阅。它与人工录制的“重启不自动续录”不同。
- 停机期间、未观看期间或失去有效订单簿时不会生成样本；重启后不会倒填这些历史。

这些是时间采样与价格分桶后的聚合库存，不是完整 L2 事件档案，也不是逐订单 MBO。页面内还有独立的内存样本；刷新页面会重建页面会话，但服务器保存的近期样本可重新读取。

## 回放与聚合能说明什么

人工录制的盘口回放从目标时点之前已收到的真实快照及连续差分重建；缺口、暂停、未录制区间或处理范围超限时返回对应不可用状态。不会把最后一帧无限延伸，也不会根据 K 线补造盘口。

成交档案可按所选范围聚合 Profile、Footprint、TPO 与 Delta/CVD。图表可视柱数截断与实际数据缺口分别呈现；Footprint 只返回部分柱时，不代表 Profile 只统计了这些柱。成交 ID 连续也不能单独证明所有历史数据都完整。

只有本地开发 / 预览服务提供这些接口。上传静态 `dist/` 不会附带 SQLite、录制或采样服务；浏览器内会话数据不能替代服务器档案。
