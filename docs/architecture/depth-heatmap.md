# 订单簿热图的数据与范围

热图在 K 线下方按时间铺开挂单量，右侧是当前深度分布。它只使用币安 USDⓈ-M 公开 L2 深度，**不是逐单 MBO，也不能补出从未被记录过的历史**。

## 深度从哪里来

| 阶段 | 说明 |
| --- | --- |
| REST 快照 | 只给最近 1000 档（BTC 约 ±$135） |
| 增量流 `@depth` | 推送整个簿的变化；`Level2Book` 会“学到”快照之外发生过变化的价位，数量为绝对值，已知价位的数量是精确的 |
| 学习范围 `horizon` | 只接受现价 ±4% 内的新价位。$1 或 10 倍价的极端挂单被忽略，簿因此有界，也不会触发 1 万档上限的整簿重置；行情大幅移动后落到范围外的价位只在簿变大时才被修剪（最远的先删） |
| 撤单 | 任何价位的数量为 0 的更新都会执行，学到的价位不会过期 |

因此暖机后深度会持续变宽：实测 BTC 约 80 秒内 ±2% 范围内的档数从 ~1300 增长到 2500+。**从未变动过的远端老挂单不会出现**，直到它们第一次变动。

## 三层保存

1. **Hub（页面内）**：`bookLevels: 6000` 档、`depthRangeRatio: 0.04`；历史每 4 秒一个样本，最多 900 个（1 小时），按“价位十进制量级 × 5e-4”（BTC $5、ETH $0.5）合并成细桶，热图步长（BTC $25、4K 模式 $10）是它们的整数倍，重新分桶不会拆分桶。
2. **服务端采样器（`server/depth-sampler.ts`）**：本地 Vite 开发 / 预览服务运行期间，对被观看的品种常驻采样，落到 `.data/depth/depth-samples.sqlite`（已 gitignore）。默认每 15 秒一个样本、保留 2 天、最多同时 3 个品种；单个样本约 4–5 KB（deflate 压缩的 int32 索引 + float32 数量）。只接受本机回环请求。
3. **合并（`prepareDepthOverlay`）**：服务端样本画在本页会话历史之前，间隔超过 2.5 个步长就断成新的连续段；价位桶与服务端返回的 `step` 不一致时不画，避免错位。

## 对用户要说清的限制

- 采样器只能从开始采样的那一刻往后积累，**重启前、未打开过该品种的时间段是空白**，换周期或刷新页面不会丢已采到的部分。
- 暖机期（约 1–3 分钟）远端价位还没学全，热图范围会逐渐变宽。
- 只有本地服务在运行时才会采样；纯静态部署没有采样接口，热图只有本页会话内的历史。
